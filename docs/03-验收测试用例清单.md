# 安全密码管家 — 验收测试用例清单

> **依据**：`reference.md` PRD V2.0 §8（六组验收项）+ `docs/01-架构规格书.md` 模块/接口
> **用例编号**：`TC-<模块>-<序号>`。优先级：P0（阻塞/必过）｜P1（重要）｜P2（常规）
> **执行约束**：任何涉及「自动删除/清空用户数据」的自动化路径 = **P0 必过且禁止出现**（PRD 总纲第 0 条）。

**模块缩写**：CRY=密钥/加密；REC=恢复/重置；AUTH=鉴权/会话；FIELD=分级鉴权；CAP=自动抓取；CLP=剪贴板；EXP=打印/导出；IMP=导入；COMP=合规/审计。

| TC-CRY-01 | 数据落库即加密 | 初始化并录入含支付密码的卡片 | 用 SQLite 工具读出原始 DB 文件内容 | 无任何明文密码片段；密文为 AES-GCM 密文 | P0 |

| TC-CRY-03 | Argon2id 参数可配置并固化 | 空库 | 检查 KDF 参数 | 参数随版本固化、可配置；代码中可审计 | P1 |

| TC-CRY-07 | 内存置空引用 | 查看密码后退出页面 | 退出后检查敏感变量引用 | 引用已置空；不保留明文对象 | P2 |

## 模块二：恢复 / 主密码重置（REC）→ PRD 8.2（核心）

| 编号 | 用例标题 | 前置条件 | 测试步骤 | 预期结果 | 优先级 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| TC-REC-01 | 连续输错不删数据 | 已存 1 条卡片 | 连续输错 5/10/20 次错误主密码 | **任何次数下原始数据均完好**；只进入锁定 | P0 |
| TC-REC-02 | 指数退避锁定 | 已解锁过 | 连续输错触发锁定 | 第 5 次锁 5min，依次翻倍；上限 30min | P0 |
| TC-REC-03 | 解锁失败显示密码提示词 | 已设置提示词 | 输错多次后点「显示提示词」 | 显示提示词；不含密码本身 | P1 |
| TC-REC-04 | 本地恢复码重置主密码 | 已生成并备份 RecoveryKey | 选「用恢复码重置」→输入恢复码→设新主密码 | 重置成功；旧数据完整可读 | P0 |
| TC-REC-05 | 邮箱/短信验证找回（两把钥匙） | 已绑定邮箱/手机 | 验证码通过→获取 RecoveryWrap→输入 RecoveryKey | 仅凭验证码**无法**解密；需两者皆备 | P0 |
| TC-REC-06 | 服务端只下发包裹 | 已绑定邮箱 | 走找回流程观察服务端响应 | 服务端仅返回 RecoveryWrap（密文），无明文密钥 | P0 |
| TC-REC-07 | 全量清除需主动+二次确认 | 有数据 | 选删除→输确认短语→再次验证 | 仅在完成上述步骤后清除；清除前可导出备份 | P0 |
| TC-REC-08 | 找回通道防中间人 | 网络抓包 | 观察找回请求 | TLS 1.3 + 一次性验证码；验证码不可复用 | P1 |

## 执行建议

1. **回归优先级**：`P0` 全量必过且阻断发布；`P1` ≥95% 通过；`P2` 抽样。
2. **自动化**：TC-CRY/TC-REC/TC-AUTH 建议做单测 + CI 校验；TC-CAP/TC-CLP/TC-EXP 建议结合 Playwright/模拟器做端到端。
3. **必过红线**（任一失败即发布失败）：
   - TC-REC-01（输错不删数据）
   - TC-REC-07（全量清除需主动确认）
   - TC-EXP-03（取消打码需二次确认）
   - TC-CAP-05 / TC-CAP-07（抓取不记录未授权输入；AutoFill 仅授权域）
   - TC-CRY-06（服务端/日志无明文密钥）
