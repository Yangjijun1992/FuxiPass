# 安全密码管家 — 数据库结构与远程接口定义

> **依据**：`docs/01-架构规格书.md` §4 密钥体系 + §5 服务模块；`reference.md` §2.2 恢复流程
> **说明**：本地 DB 用 SQLCipher（密钥 = DEK）；远程层为**可选、零知识**（仅邮箱/短信找回）。所有表字段仅存**密文**，禁止存明文凭证。

---

## 1. 本地数据库（SQLCipher，加密密钥 = DEK）

### 1.1 元数据表 `meta`（单行，存放包裹与 KDF 参数）

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | INTEGER PK | 恒为 1（单例） |
| `schema_version` | INTEGER | 结构版本，用于迁移 |
| `kdf_algo` | TEXT | `Argon2id` |
| `kdf_salt` | BLOB | 主密码派生盐 |
| `kdf_m` / `kdf_t` / `kdf_p` | INTEGER | Argon2id 内存/迭代/并行度 |
| `dekwrap` | BLOB | KEK 包裹的 DEK（`DEKWrap`，JSON 序列化） |
| `recoverywrap` | BLOB | Recovery Key 包裹的 DEK（`RecoveryWrap`） |
| `hint` | TEXT | 密码提示词（本地，可空，**勿含密码**） |
| `forced_mp_ts` | TEXT | 上次强制主密码时间，用于 24h 策略 |

**DEKWrap / RecoveryWrap 序列化 JSON 示例**（字段名与 `security_core` 的 serde 输出严格一致）：
```json
{
  "version": 1,
  "kdf": {"algorithm":"argon2id","salt":"BASE64","m_cost_kib":19456,"t_cost":2,"p_cost":1},
  "cipher": {"algorithm":"aes-256-gcm","nonce":"BASE64(NONCE96)","tag":"BASE64(TAG128)"},
  "ciphertext": "BASE64(不含tag)"
}
```
> 说明：`kdf` 仅 DEK 包裹存在（供日后由主密码重新派生 KEK）；RecoveryKey 包裹中 `kdf` 为 `null`（恢复密钥直接作 AES-256 密钥，无需 KDF）。`ciphertext` 与 `tag` 分离存储，解密时将两者拼接。`m_cost_kib` 为 Argon2id 内存代价（KiB，19 MiB = 19456）。

### 1.2 账号卡片表 `accounts`

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | TEXT PK | UUID |
| `app_name` | TEXT | 应用/网站名 |
| `url` | TEXT | 网址 / 应用包名（可空） |
| `username` | TEXT | 账号（**可用 FDEK 加密**，级别=中） |
| `notes` | TEXT(ENCRYPTED) | 备注（级别=高，含密保答案，FDEK） |
| `importance_label` | TEXT | 常用/金融银行/低频备用/社交 |
| `created_at` / `updated_at` | TEXT | 时间戳 |

> 建议把 `username`/`notes` 也纳入字段加密（`secret_fields`），而非整卡单密文，以支持字段级权限。

### 1.3 高敏感字段表 `secret_fields`（二级密码/支付密码/密钥/TOTP）

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | TEXT PK | UUID |
| `account_id` | TEXT FK | 关联 `accounts.id` |
| `field_type` | TEXT | `secondary_password` / `payment_password` / `api_key` / `private_key` |
| `ciphertext` | BLOB | **FDEK 加密**密文（未二次验证不可解） |
| `masked_preview` | TEXT | 脱敏预览（`88****`），用于列表无需解密 |
| `requires_2fa` | BOOLEAN | 默认 true |
| `created_at` | TEXT | 时间戳 |

### 1.4 授权域表 `autofill_domains`（抓取/AutoFill 信任边界）

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | TEXT PK | UUID |
| `domain_or_pkg` | TEXT | 网址域 或 应用包名 |
| `list_type` | TEXT | `whitelist` / `blacklist`（黑名单优先） |
| `enabled` | BOOLEAN | 是否启用该规则 |
| `created_at` | TEXT | 时间戳 |

> 抓取全局开关存 `app_prefs`（非敏感，可本地键值存储），默认 `false`。

### 1.5 审计日志表 `audit_logs`

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | INTEGER PK | 自增 |
| `ts` | TEXT | 操作时间 |
| `operation` | TEXT | `view`/`copy`/`edit`/`export`/`print` |
| `field_category` | TEXT | 仅字段**类别**，不落明文值 |
| `account_id` | TEXT | 可控（用于追溯，可选） |

> 满足 PIPL 审计要求：可查询、可导出；**禁止**记录明文密码/密钥。

### 1.6 恢复绑定表 `recovery_binding`（可选，远程找回用）

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `id` | TEXT PK | UUID |
| `contact_hash` | TEXT | 邮箱/手机号 **不可逆哈希**（不存明文，防泄露） |
| `contact_type` | TEXT | `email` / `sms` |
| `recoverywrap_remote` | BLOB | 服务端持有的 RecoveryWrap（解密用 RecoveryKey 在客户端） |
| `verified` | BOOLEAN | 是否已绑定 |

## 2. 远程恢复 API 契约（可选，零知识）

> **零知识边界声明**：服务端仅存 `contact_hash`（不可逆）与 `recoverywrap_remote`（密文）。服务端**永不接收、永不观测**主密码、KEK、Recovery Key。恢复的解密必须在客户端完成。

**通用约定**：HTTPS/TLS 1.3；所有请求/响应 JSON；`Authorization` 用短期令牌；遇到非 2xx 不泄漏用户存在性；失败走通用错误 `{ "error":{"code":..., "message":"..."} }`。

### 2.1 发起验证码
```
POST /v1/recovery/challenge
Req:  { "contact": "139****1234" }   ← 传输时可按需用一次性 Token 匿名化
Resp: { "request_id": "req_xxx", "challenge": "sms", "ttl_sec": 600 }
```
- 服务端不存明文 `contact` 全文，转发验证码后立即丢弃（或只存哈希）。
- 返回通用成功，避免枚举真实已绑定账号（**防探测**）。

### 2.2 校验验证码并请求包裹
```
POST /v1/recovery/verify
Req:  { "request_id":"req_xxx", "code":"123456" }
Resp: { "token":"jwt_shortlived", "recoverywrap_remote":"BASE64", "expires_in":120 }
```
- 验证码**一次性**、不可复用；`token` 为短寿命访问令牌（用于后续获取包裹）。
- **要点**：此响应只含 `recoverywrap` 密文；客户端仍需用户输入 Recovery Key 才能解包 → **两把钥匙**。

### 2.3 获取恢复包裹（再次校验 token）
```
POST /v1/recovery/wrap  (Authorization: Bearer <token>)
Resp: { "recoverywrap":"BASE64", "kdf": {...}, "version":1 }
```
- 或由 2.2 直接返回包裹，则本步可选。为安全分开，让其走一次短令牌，防止中间人重放。

### 2.4 错误码
| code | 含义 |
| :-- | :-- |
| `INCORRECT_CODE` | 验证码错误（含剩余尝试次数，防止爆破） |
| `CODE_EXPIRED` | 验证码过期 |
| `RATE_LIMITED` | 请求过于频繁 |
| `NOT_BOUND` | 未绑定邮箱/手机 |

**安全措施**：
- 验证码 6 位、有效期 5 分钟；同一 target 限制频率 + 尝试次数上限（如 5 次失败即退避）。
- 所有错误为通用文案，防止**账号枚举**。
- 服务端日志/监控**不落**明文验证码、明文 contact、Recovery Key。

## 3. 关键校验（连到验收）

| 规则 | 验收用例 |
| :-- | :-- |
| 本地 DB 未出现明文凭证 | TC-CRY-01 |
| 服务端/日志无主密码/KEK/RecoveryKey 明文 | TC-CRY-06 |
| 仅凭验证码无法解包，需 Recovery Key | TC-REC-05 |
| 服务端只下发 RecoveryWrap | TC-REC-06 |
| 绑定只存不可逆哈希 | TC-COMP-06 |
