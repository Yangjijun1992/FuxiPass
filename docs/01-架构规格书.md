# 安全密码管家 — 技术架构规格书

> **对应用**：`reference.md`（PRD V2.0 安全加固版）
> **版本**：V1.0
> **目的**：把 PRD 的「安全原则 + 验收项」落成可实现的**模块化架构**，供研发拆分任务、供 QA 编写测试用例。本文是 `02-开发任务清单.md` 与 `03-验收测试用例清单.md` 的**唯一架构依据**，三份文档术语必须一致。

---

## 1. 架构设计目标

| 目标 | 说明 |
| :-- | :-- |
| 零知识可恢复 | 服务端永不可读明文；主密码遗忘可通过密码提示/恢复码/邮箱短信找回，**绝不丢数据** |
| 密码学分层 | 主密码只派生 KEK，不直接加密数据；DEK 负责全量数据；Recovery Key 负责灾难恢复 |
| 权限最小化 | 抓取 / AutoFill 等高风险能力默认关闭、授权域白名单、逐项授权 |
| 跨平台一致 | Android / iOS 安全能力差异化（Keystore vs Keychain、FLAG_SECURE 差异）用平台适配层隔离 |
| 可测试 | 每个模块对应 PRD §8 验收项（8.1–8.6），任务/用例可追溯到需求 |

## 2. 总体分层架构

```
┌────────────────────────────────────────────────────────┐
│  UI 层 (Presentation)                                  │
│  Flutter：主界面 / 详情页 / 卡片 / 检索 / 打印预览 / 找回界面 │
│  组件复用，调业务层契约，不直接触碰加密/持久化               │
└──────────────────────────┬─────────────────────────────┘
                           │ 业务契约 (domain interfaces)
┌──────────────────────────┴─────────────────────────────┐
│  业务服务层 (Services)                                  │
│  AuthService / RecoveryService / FieldProtectionService │
│  ClipboardService / PrintExportService / ImportService  │
│  CaptureService / AutoFillBridge / AuditService         │
└──────────────┬───────────────────────────┬────────────┘
               │                            │
┌──────────────┴─────────────┐   ┌─────────┴────────────────────────┐
│ 安全核心层 (SecurityCore)    │   │ 数据持久化层 (Storage)           │
│ CryptoCore(Argon2id/AES-GCM │   │ Repository / 加密卡片模型         │
│ /KeyHierarchy/KeyStore)     │   │ SQLCipher(DEK) / 密钥包裹存储     │
│ BiometricSession /          │   │ 审计日志存储(仅元数据)            │
│ SafeClipboard / FDEK        │   │ 文件缓存(导入/导出临时)            │
└──────────────┬─────────────┘   └───────────┬────────────────────┘
               │                              │
┌──────────────┴──────────────────────────────┴───────────────────┐
│ 平台适配层 (Platform Adaptor, Kotlin/Swift via method-channel)   │
│ AndroidKeystore / iOSKeychain / IdentifierForVendor / Keychain   │
│ BiometricPrompt / LocalAuthentication / FLAG_SECURE / SafeArea   │
│ AutoFill Service / Accessibility Service / ShareExtension       │
└─────────────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────────────┐
│ 远程服务层 (Remote, 可选 & 零知识)                                │
│ Email/SMS MFA 验证、Recovery 包裹上传/下发、找回令牌             │
│ 仅存包裹(y=包裹密文) 无明文，服务端无可解密密钥                   │
└─────────────────────────────────────────────────────────────────┘
```

**设计原则**：
- 加密与密钥操作集中在 `SecurityCore`，UI/业务层**不得**出现裸密钥或明文持久化。
- 平台差异（Keystore/Keychain/FLAG_SECURE/AutoFill/无障碍）统一封装进**平台适配层**，业务层不感知平台。
- 远程层**可选**：未绑定邮箱/手机用户走「纯本地 + 恢复码」模式，核心功能完全离线可用。

## 3. 核心技术选型

| 层 | 推荐 | 理由 |
| :-- | :-- | :-- |
| UI/跨端 | **Flutter (Dart)** | 三端一致性高；安全关键逻辑下放原生，UI 层不承担密钥职责 |
| 安全/加密（原生） | **Android: Kotlin + Google Tink / 原生 Keystore**；**iOS: Swift + CryptoKit / Security.framework** | Argon2id、AES-256-GCM、key-wrapping 用成熟库，避免自实现密码学 |
| 密钥派生 | **Argon2id**（基准 `m=19MiB, t=2, p=1`，高端设备可上调到 64MiB；生产需在文档固化并审计） | PRD §4 要求；抗 GPU/ASIC 暴力破解 |
| 加密算法 | **AES-256-GCM**（96-bit 随机 nonce + 128-bit tag），每字段独立 nonce | 认证加密，且每密文区不同 nonce |
| 持久化 | **SQLCipher**（数据库级加密，密钥 = DEK） | 防文件拷贝/拔盘破解 |
| 生物识别 | Android `BiometricPrompt` + `setUserAuthenticationRequired`；iOS `LocalAuthentication` | 仅解锁短期会话，24h 强制主密码 |
| 剪贴板 | Android `ClipboardManager` 监听 + iOS `UIPasteboard` + 计时器 | 普通字段自清空；高敏感默认不写系统剪贴板 |
| 网络(可选) | HTTPS/TLS 1.3 + 一次性验证码 + 短时令牌 | 邮箱/短信找回；恢复包裹仅密文 |
| 解析导入 | Dart 编写非结构化解析器 + 规则表 | QQ 记事本/备忘录文本；可离线 |

> ⚠️ **强制约束**：**禁止自研密码学算法**；所有密钥派生/加解密必须走上述成熟库，且结果需通过 `03-验收测试用例清单` 的密码学用例。

## 4. 密钥体系（与 PRD §2.1 一致，此处给实现细节）

| 密钥 | 规格 | 生成 | 存储 | 用途 |
| :-- | :-- | :-- | :-- | :-- |
| KEK | 不定长 | 主密码 → Argon2id（盐随机/每库一份） | 不存储，即时派生 | 包/解包 DEK |
| DEK | 256-bit | 初始化 CSPRNG | KEK 包裹密文入库 | AES-256-GCM 加密全量数据 |
| Recovery Key | ≥128-bit 熵 | 初始化 CSPRNG → Base58 分组显示 | 仅用户持有（可导出/打印） | 灾难恢复，重包 DEK |
| Account Key | 256-bit | 初始化 | OS Keystore/Keychain（受生物+TEE） | 快捷解锁短期会话 |

**包裹格式（均含版本号与 KDF 参数，便于升级）**：
```
DEKWrap = { version, kdf: {algo:Argon2id, salt, m, t, p}, cipher:AES-256-GCM, nonce, ciphertext }
RecoveryWrap = { version, kdf: {algo:Argon2id, salt, m, t, p}, cipher:AES-256-GCM, nonce, ciphertext }
AccountKey → 仅存于 OS 安全硬件，不进数据库
```

**关键控制流**：
```
解锁:  主密码 → Argon2id → KEK → 解密 DEKWrap → DEK → SQLCipher 可用
快捷:  生物识别 → OS 解锁 AccountKey → 开启会话(<=2min 或 24h 强制主密码)
修改主密码: 重派生 KEK → 重包 DEKWrap（不重加密全量数据）
找回:  验证码 → 取 RecoveryWrap → 用户输入 RecoveryKey → 解包 DEK → 设新主密码
```

**字段级权限（可选增强，建议 Phase 2 起）**：高敏感字段（二级/支付/密钥/密保备注）用 **FDEK** 单独加密，未二次验证时解密失败，实现「字段密文在库中即不可读」的**真字段级权限**，而非仅 UI 拦截。

## 5. 业务服务层模块设计（每模块给出职责 + 关键接口契约）

> 接口签名仅示意层，由研发按语言序列化落地。每个接口都应当有对应密码学/业务单元测试。

### 5.1 AuthService（认证与会话）
- 职责：主密码解锁、生物识别会话、24h 强制主密码、防爆破退避锁定。
- 关键接口：`unlock(masterPassword)`, `bioUnlock()`, `unlockSession`, `verifySecondFactor(kind)`, `isSensitiveActionAllowed(field)`, `scheduleForcedMasterPassword()`.

### 5.2 RecoveryService（恢复/重置 — PRD §2.2 核心）
- 职责：密码提示词、本地恢复码、邮箱/短信验证（两把钥匙）。
- 关键接口：`setHint()`, `getHint()`, `generateRecoveryKey()`, `exportRecoveryKey()`, `requestEmailSmsCode()`, `verifyCode(code) → returns RecoveryWrap`, `resetMaster(wrap, recoveryKey, newPassword)`.

### 5.3 FieldProtectionService（分级鉴权，PRD §3.4）
- 职责：字段分级映射（普通/中/高/极高）、二次验证触发、会话 2 分钟时效、FDEK 解密门控。
- 关键接口：`classifyField(name)`, `requireSecondFactor(field, action)`, `decryptField(fieldId, authToken)`, `invalidateSession()`.

### 5.4 ClipboardService（剪贴板策略，PRD §3.5.3）
- 职责：普通字段 30s 自清空 + 多次复制重置；高敏感字段默认不写系统剪贴板 / 受控复制 + 强警示。
- 关键接口：`copyCleared(text, fieldLevel)`, `clearAfter(seconds)`, `isHighSensitive(level)`, `securePastePanel(text)`.

### 5.5 PrintExportService（打印/导出，PRD §3.5.4）
- 职责：默认打码（`88****`）、取消打码二次确认、二次验证、加密备份导出 + 导入恢复。
- 关键接口：`maskField(field)`, `previewPrint(account, {mask:true})`, `confirmUnmask(field)`, `exportEncrypted(password|recoveryKey)`, `importFromEncrypted(file)`.

### 5.6 ImportService（QQ/备忘录解析，PRD §3.3）
- 职责：非结构化文本解析成字段、表格预览、校验（必填去重）、主密码验证后批量入库。
- 关键接口：`parse(rawText) → [CandidateAccount]`, `validate(candidate)`, `importApproved(list)`.

### 5.7 CaptureService（自动抓取，PRD §3.2 — 高权限收敛）
- 职责：登录页识别、授权域白名单 + 黑名单优先级、只读表单字段、预览脱敏、不落盘不写日志。
- 关键接口：`isEnabled()`, `isInWhitelist(url)`, `detectLoginForm()`, `onLoginSuccess(payload)`, `addToWhitelist/Blacklist`, `capturePreview(payload)`.

### 5.8 AutoFillBridge（AutoFill，PRD §3.6）
- 职责：Android AutoFill Service / iOS Keychain AutoFill 回调，授权域内主动回填。
- 关键接口：`onInvoked(ctx)`, `resolveCredentials(url) → 脱敏列表`, `fill(dek)`, `decline()`.

### 5.9 AuditService（审计 — PRD §7 合规）
- 职责：记录高敏感操作「时间 + 字段类别 + 是否导出」，**不落明文**；可查询导出。
- 关键接口：`logSensitive(operation, fieldCategory)`, `queryLogs(range)`, `exportLogs()`.

### 5.10 PlatformAdaptor（平台适配 — 差异隔离）
- 职责：Keystore/Keychain 读写、BiometricPrompt/LocalAuthentication、FLAG_SECURE / iOS 前台防录屏、AutoFill/无障碍注册、SafeArea。
- 关键接口：`storeAccountKey(key)`, `loadAccountKey()`, `authenticateBiometric()`, `setSecureFlag(on)`, `enableAutoFill(domains)`.

## 6. 数据流（关键路径）

```
[录入/抓取/导入] → 明文(内存) → 字段分级 → FieldProtection → FDEK(高敏感) → DEK(AES-GCM)
                → Repository → SQLCipher 落库
[读取]
   显式主密码/生物会话解密 → 分级门控(二次验证?) → 明文(仅显示瞬态) → 退出置空引用
[找回/导出]
   RecoveryKey 加密包裹 ↔ 本地导出 / 邮箱短信验证下发包裹
[审计]
   高敏感访问 → 记录(时间+类别) → 审计存储(非明文)
```

**明文生命周期约束**：完成即置空引用、可配置内存擦除；导入/导出临时文件用安全目录并即时清理。

## 7. 威胁模型与防御措施

| 威胁 | 攻击场景 | 防御（模块） |
| :-- | :-- | :-- |
| 设备丢失 / 文件拷贝 | 拿到加密 DB 文件 | SQLCipher（DEK）+ KeyHierarchy，顶格加密 |
| 主密码暴力破解 | 攻击者离线爆破 | Argon2id（高开销）+ 主密码强度策略（8.1 验收）+ 退避锁定 |
| 离线破解备份/密文 | 拿到 RecoveryWrap / DEKWrap | RecoveryKey 高熵 + 主密码强度（弱密码=离线可破） |
| 恶意应用读剪贴板 | 第三方读取复制内容 | ClipboardService：高敏感默认不写剪贴板 |
| 屏幕录制/截图 | 记录明文密码界面 | FLAG_SECURE（Android）+ iOS 前台检测 |
| 服务端泄露 | 绑定邮箱/找回服务被攻破 | 零知识：只存包裹，无明文、无解密密钥 |
| 内存 dump | 进程内存被读取 | 专用容器 + 置空引用；明确托管语言无法物理清零（见 PRD §4) |
| Root / Jailbreak | 提权读取 | 检测 + 降级说明 + 拒绝敏感功能（可选） |
| 解析注入 | 导入恶意文本 | ImportService：模板化字段提取，无执行，输入校验 |
| 中间人（找回通道） | 拦截验证码 | TLS 1.3 + 一次性验证码 + 恢复码双钥匙 |

**零知识边界**：服务端仅可上/下发 `RecoveryWrap`，无用户主密码、KEK、RecoveryKey，故即使被攻破也无法解密。

## 10. 风险与边界（研发须知）

1. **内存清零不可保证**：托管语言（Dart/Kotlin/Swift）无法可靠物理清零内存。采用「敏感专用容器 + 完成置空引用 + 不复用字符串」缓解，勿承诺绝对清零。
2. **抓取权限合规**：Android 无障碍/浏览器「读取所有输入」可能触发商店风控与隐私审查，需「默认关闭 + 授权域 + 隐私声明」并可用；
3. **iOS 无对等 FLAG_SECURE**：防录屏只能做前台检测/证书越狱检测等弱化方案，需在文档与 UI 中弱化威胁声明，如实告知用户。
4. **RecoveryKey 若丢失且绑定邮箱/手机不可用** = 数据不可恢复。首次初始化必须强提示用户备份 RecoveryKey。
5. **KDF 参数需在版本中固化**，升级时保证旧数据仍可解；换参数需覆盖迁移用例。
